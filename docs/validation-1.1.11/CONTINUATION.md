# 1.1.11 继续实施记录

本轮继续用户批准但尚未正式发布的 1.1.11，不把之前的工程候选认定为完整交付。`Delivery` 原始证据、99e0ef4 成品和交接包保持不变；以下公共产品修改必须由新提交重新构建 Windows、两种 Mac 和两种 Linux，旧成品不能为新代码背书。

## 本轮已确定问题及修复

- Linux 陶瓦 0.4.2 使用继承的临时目录保存服务锁。每次启动改用产品专属 `mkdtemp` 目录，仅结束自己创建的进程组，并等到组退出才清理该目录。其他启动器服务、既有用户文件和游戏进程不属于清理范围。
- 账号页曾把令牌存储写成 Windows 专用实现。提示改用真实系统返回的凭据存储状态；获取失败或尚未确认时不显示已安全保存。
- 卡慕队列的可观察值过去只在动画回调中更新。接受/拒绝点击后同步发布本实例观察计数和队列长度；32 上限、动画时间线、声音、历史计数与增量保存逻辑保持原样。
- 固定鸿蒙 37.2 模板曾发送异步退出后立即终止。系统请求改为取消直接终止，保留关闭意图，等待 native binding 和真正 Browser 启动后交由现有产品状态机处理。只在 Electron 完成 quit 后允许最终原生终止。
- 鸿蒙标准目录对话与 Chromium 目录选择原来没有等待持久授权成功。两条路径均等待真正 picker URI 的授权和记录 flush，串行合并多目录，失败返回取消。普通文件不扩大授权。旧目录激活失败明确提示重试，或者由用户选择继续后重新选择目录，不记为授权恢复成功。

`scripts/harmony-native-adaptations.cjs` 固定十个真实维护方模板源文件 SHA256，拒绝未审核的模板变化。故障测试执行生成的方法，覆盖提前关闭、Browser 未就绪、取消后再次关闭、拒绝与重试、并发授权、磁盘保存失败、标准/混合选择及可见的恢复失败。**这些是序列逻辑测试；没有官方 SDK 编译与真实设备结果，不能认定 ArkTS 合法、实际授权或原生游戏运行通过。**

## 正在补齐的原生验证

Mac 新入口在独立 profile 运行四主题、15 页面、三种常用缩放及最小窗口；逐点击记录接受、拒绝、接触、声音和增量保存；同一 profile 实际重启核对离线账号、设置、收藏和计数；公开 Modrinth 资源使用真正服务及下载哈希。旧 Intel WebGL 失败继续保留。

Linux 新入口分别运行真实官方 FRP/陶瓦及本机架构文件，核查独立服务生命周期；账号、设置、收藏、更新包和 X11 窗口后端使用限定夹具/隔离文件运行。Xvfb、纯后端或同版本更新交易不替代 GNOME/KDE/Wayland 原生桌面、真实账号、跨版本更新和进入世界。

完整范围仍为 15 页面、280 接口、63 个验收场景及各场景全部子项。缺少原生证据、真实服务或人工听感时保持未覆盖。三项独立评分分别达到 9/10、无关键缺陷且全部必测完成后才可正式发布；不改写已有失败、原帧时间或门槛。

发布检查固定原 280 个接口名称、63 个功能定义和 481 个明确子断言。结构化观察需绑定原始运行记录，不能用单一通过布尔值、库存存在或静态测试替代。原生 BGRA 检查保留全部回调、原始 PTS、状态、步长、窗口身份、固定区域及无损 PNG 的逐像素反核。

这些保护只能核验可信采集器输出之间的完整性和一致性。任意自造的记录不能凭摘要自证真实运行；两张不同图片交替也不能证明动作流畅。正式评分仍需要独立查看实际运行、完整操作和原始录屏。首次 932 项公开检查中非法原步长被正确拒绝，但测试错误文字匹配失败；原失败日志保留，明确错误提示后重新运行。原录屏状态矛盾的协议缺口另补校验，不改动已采集帧或时间。

## 仍需外部条件

用户已确认没有真实 Intel Mac；当前云端 Intel 虚拟图形设备的默认 WebGL 初始化失败，尚无合格环境完成验收。Linux 正式桌面机器与原生 ARM64 桌面尚未取得。鸿蒙缺官方 DevEco/SDK、产品签名及电脑，且本地 JVM/JNI/GLFW/音频和 HNP 子进程链尚未完成；原生界面工程不能代替游戏功能。运行时许可完整性仍需补齐后方可公开 HAP。

最终结果以新提交对应的原始日志、截图、录屏和摘要为准；本文件是实施记录，不是通过证明。

## 点击观察器修正与成品来源

新 Windows 四主题独立实际操作已完成，每主题 40 次可信点击对应 32 次接受、8 次拒绝、32 次接触和实际掌击音源；计数与磁盘读取一致，关闭音频并恢复焦点。598 个原始 JPEG 的顺序、时间、大小、摘要与模型区域变化已独立核对。CDP 采集频率只是该采集器指标，不等于系统原生呈现帧率；人工听感和完整功能矩阵仍未覆盖。

实际点击暴露了验收观察器的时序错误：在 document 捕获监听器安排的微任务可能早于 Vue 目标处理器执行，错误地把接受后的队列读成接受前。观察器改为以同一个原始 Event 绑定捕获阶段（1）的前值与冒泡阶段（3）的后值；继续逐项校验原队列变化、接受/拒绝、接触、音源、保存计数及时间。两个新增合成事件阶段回归测试明确不属于实际 GUI 通过证据。原始失败与原观察值不回填。

Windows 四主题验证使用产品提交 `2d814479b22b8778c80bbbdf8b04421a81cf9c47` 的实际 EXE。后续仅验收脚本、测试或状态文档变化时保留该成品来源，交接报告另外列出最终源码提交与两者完整差异。Mac/Linux 新一轮运行以自己的实际构建提交和原始身份记录为准，不把旧包绑定到未来提交。工程候选仍没有正式版本标签或 Release。

同源 Mac 运行 `37180466339` 的 17 个任务已结束：12 成功、5 失败。失败包括两项 Intel APP/DMG 的默认 WebGL 初始化、两架构完整导航后的旧微任务观察断言，以及 ARM 工具的第二次产品 API 就绪断言。实际模型、游戏、更新等通过仅限各自原始记录的范围。ARM 工具在断言处缺少产品阶段原状态，不能根据 15 秒观察上限与产品 120 秒启动上限推断本次必然属于过早断言。

工具验收增加在应用就绪与下载之前落盘的身份、阶段开始/结束、原状态、原消息和自己创建的进程记录。总截止时间只使挂起的隔离验收非零失败，并为清理与记录留时间；原 API 就绪条件、轮询次数、哈希、版本和产品超时不放宽。诊断磁盘写入故障与原操作失败分别记录，不能阻断原回调或跳过清理；清理启动后拒绝新的测试子进程。下一轮以新原始状态继续定位，不重写上轮结果。

Linux 三个旧工具步骤的取消另外定位出确定的验收入口缺陷：Electron 44 的官方 default-app 用动态 import 加载指定 CJS，旧 `require.main === module` 条件不成立，工具和业务主程序因此未执行。官方两架构加载档案已核对，Windows 同版实际隔离 Electron 进程也观测到 `require.main.filename` 为 `electron`、条件为 false，并正常就绪退出。入口改为辨认真正的 CLI 主文件，普通模块导入不能启动验收；另用匹配架构的真实 Electron 短进程复核。旧取消结果不归为产品下载或服务失败，也不能视作后台业务已执行。
